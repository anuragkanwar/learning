# Primary Key & Foreign Key — SQL Commands

:::note

PK enforces **entity integrity** (every row is uniquely identifiable). FK enforces **referential integrity** (relationships stay valid).
:::

## Execution Order (DDL)

```text
1. Data type check    → valid integer/text?
2. NOT NULL check     → value present?
3. UNIQUE / PK check  → value unique?
4. CHECK constraint   → condition met?
5. FK referential     → referenced row exists?
```

## Reference Schema

```plsql
CREATE TABLE users (
    id          SERIAL PRIMARY KEY,
    username    VARCHAR(50) NOT NULL UNIQUE,
    email       VARCHAR(255) NOT NULL UNIQUE,
    full_name   VARCHAR(100) NOT NULL,
    age         INT CHECK (age >= 13),
    is_active   BOOLEAN DEFAULT TRUE,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE products (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    price       NUMERIC(10,2) NOT NULL CHECK (price > 0),
    stock_qty   INT NOT NULL DEFAULT 0 CHECK (stock_qty >= 0)
);

CREATE TABLE orders (
    id            SERIAL PRIMARY KEY,
    user_id       INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    order_date    TIMESTAMPTZ DEFAULT NOW(),
    status        VARCHAR(20) DEFAULT 'pending'
                  CHECK (status IN ('pending', 'shipped', 'delivered', 'cancelled'))
);

CREATE TABLE order_items (
    id            SERIAL PRIMARY KEY,
    order_id      INT NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    product_id    INT NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    quantity      INT NOT NULL CHECK (quantity > 0),
    unit_price    NUMERIC(10,2) NOT NULL CHECK (unit_price >= 0)
);
```

## PRIMARY KEY

`PRIMARY KEY` = `NOT NULL` + `UNIQUE`. Automatically creates a unique B-tree index.

### Syntax — 3 Ways

```plsql
-- Method 1: Column-level (single column only)
CREATE TABLE users (id SERIAL PRIMARY KEY);
-- Auto-named: users_pkey

-- Method 2: Table-level (required for composite, allows naming)
CREATE TABLE users (
    id SERIAL NOT NULL,
    CONSTRAINT pk_users PRIMARY KEY (id)
);

-- Method 3: GENERATED AS IDENTITY (PG10+, preferred over SERIAL)
CREATE TABLE users (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
);
-- GENERATED ALWAYS = manual inserts blocked
-- GENERATED BY DEFAULT = manual inserts allowed
```

### Behind the Scenes

```plsql
CREATE TABLE test (id INT PRIMARY KEY);

-- PK creates:
--   1. NOT NULL on column
--   2. Unique B-tree index (named test_pkey)
--   3. Entry in pg_constraint (contype = 'p')

SELECT conname, contype FROM pg_constraint
WHERE conrelid = 'test'::regclass;
--  test_pkey | p
```

### Composite PK

```plsql
-- 2+ columns, no single column is unique but combination is
CREATE TABLE order_items_composite (
    order_id    INT NOT NULL,
    product_id  INT NOT NULL,
    quantity    INT NOT NULL CHECK (quantity > 0),
    unit_price  NUMERIC(10,2) NOT NULL,

    CONSTRAINT pk_order_items PRIMARY KEY (order_id, product_id),

    CONSTRAINT fk_items_order FOREIGN KEY (order_id)
        REFERENCES orders(id) ON DELETE CASCADE,
    CONSTRAINT fk_items_product FOREIGN KEY (product_id)
        REFERENCES products(id) ON DELETE RESTRICT
);
```

**Use when:** Junction tables (M:N), weak entities, versioned data.

**Surrogate vs Composite for junction tables:**

| Aspect | Surrogate PK | Composite PK |
|--------|-------------|--------------|
| Uniqueness | Needs separate `UNIQUE(order_id, product_id)` | Built-in |
| FK refs | Other tables ref `order_items.id` | Other tables need both columns |
| Index count | 2 (PK + unique index) | 1 (PK index covers both) |
| Join | `JOIN ON items.id = x.id` | `JOIN ON a=x.a AND b=x.b` |
| Use when | Table is referenced elsewhere | Table is terminal (no children) |

:::tip Leftmost Prefix Rule

`PK(a, b, c)` index works for queries on `a`, `a+b`, `a+b+c`. Queries on only `b` or `c` do NOT use the index — they trigger a full scan.
:::

## FOREIGN KEY

Ensures a value in one table **exists** in another table's PK (or UNIQUE). Prevents orphan rows.

### Syntax — 2 Ways

```plsql
-- Method 1: Column-level (single column only)
CREATE TABLE orders (
    user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE
);
-- Auto-named: orders_user_id_fkey
-- ON DELETE defaults to NO ACTION if omitted

-- Method 2: Table-level (required for composite, allows naming)
CREATE TABLE orders (
    user_id INT NOT NULL,
    CONSTRAINT fk_orders_users FOREIGN KEY (user_id)
        REFERENCES users(id) ON DELETE CASCADE
);
```

:::warning

No index is auto-created for FKs. You must create indexes on FK columns manually — otherwise every FK JOIN triggers a sequential scan.
:::

### ON DELETE / ON UPDATE Actions

```plsql
CREATE TABLE orders (
    user_id INT NOT NULL
        REFERENCES users(id)
        ON DELETE CASCADE     -- what happens when user is deleted
        ON UPDATE CASCADE     -- what happens when user.id changes
);
```

| Action | ON DELETE (parent deleted) | ON UPDATE (parent PK changes) |
|--------|---------------------------|------------------------------|
| `NO ACTION` (default) | Blocks delete — error | Blocks update — error |
| `RESTRICT`| Blocks delete — immediate check | Blocks update |
| `CASCADE` | Deletes child rows | Propagates PK to child FKs |
| `SET NULL` | Sets child FK to NULL | Sets child FK to NULL |
| `SET DEFAULT` | Sets child FK to DEFAULT | Sets child FK to DEFAULT |

:::warning Cascading Deletes

`CASCADE` chains: `DELETE FROM users` → cascades to `orders` → cascades to `order_items`. Limit to 2-3 levels. Deep cascading can delete large portions of your database silently.
:::

### Composite FK

```plsql
-- Parent with composite PK
CREATE TABLE product_variants (
    product_id      INT NOT NULL,
    variant_code    VARCHAR(20) NOT NULL,  -- 'RED-XL', 'BLUE-M'
    variant_name    VARCHAR(100) NOT NULL,
    price_adjust    NUMERIC(10,2) DEFAULT 0,
    CONSTRAINT pk_product_variant PRIMARY KEY (product_id, variant_code),
    CONSTRAINT fk_variant_product FOREIGN KEY (product_id)
        REFERENCES products(id) ON DELETE CASCADE
);

-- Child referencing with composite FK
CREATE TABLE variant_inventory (
    product_id      INT NOT NULL,
    variant_code    VARCHAR(20) NOT NULL,
    warehouse_id    INT NOT NULL,
    quantity        INT NOT NULL CHECK (quantity >= 0),
    CONSTRAINT pk_variant_inventory PRIMARY KEY (product_id, variant_code, warehouse_id),
    CONSTRAINT fk_inventory_variant FOREIGN KEY (product_id, variant_code)
        REFERENCES product_variants(product_id, variant_code)
        ON DELETE CASCADE
);
```

**Requirements:** Same column count, compatible types, same order, target must be unique.

**Joining composite FK requires all columns:**
```plsql
JOIN product_variants pv
    ON pv.product_id = vi.product_id AND pv.variant_code = vi.variant_code
```

### Self-Referencing FK

```plsql
CREATE TABLE employees (
    id              SERIAL PRIMARY KEY,
    name            VARCHAR(100) NOT NULL,
    manager_id      INT REFERENCES employees(id) ON DELETE SET NULL
);

-- Insert org chart
INSERT INTO employees VALUES
    (1, 'Alice CEO',   NULL),
    (2, 'Bob VP Eng',  1),
    (3, 'Carol VP Mkt', 1),
    (4, 'Dave Dev',    2),
    (5, 'Eve Dev',     2);

-- Direct reports
SELECT name FROM employees WHERE manager_id = 2;  -- Dave, Eve
-- Manager of Bob
SELECT e2.name FROM employees e1
JOIN employees e2 ON e1.manager_id = e2.id
WHERE e1.name = 'Bob VP Eng';  -- Alice CEO
```

:::tip

For org charts, `ON DELETE SET NULL` is safest — deleting a manager keeps their reports (with `manager_id` set to NULL). `ON DELETE CASCADE` would delete all reports when a manager is removed.
:::

## ALTER TABLE — PK / FK Management

```plsql
-- Add PK (table must have unique, non-null values)
ALTER TABLE users ADD PRIMARY KEY (id);
ALTER TABLE users ADD CONSTRAINT pk_users PRIMARY KEY (id);
ALTER TABLE order_items ADD CONSTRAINT pk_oi PRIMARY KEY (order_id, product_id);

-- Must make column NOT NULL first if it isn't
ALTER TABLE users ALTER COLUMN id SET NOT NULL;

-- Drop PK
ALTER TABLE users DROP CONSTRAINT users_pkey;
ALTER TABLE users DROP CONSTRAINT users_pkey CASCADE;  -- drops all FKs referencing this PK

-- Add FK
ALTER TABLE orders ADD CONSTRAINT fk_orders_users
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE;

-- Composite FK
ALTER TABLE variant_inventory ADD CONSTRAINT fk_inventory_variant
    FOREIGN KEY (product_id, variant_code)
    REFERENCES product_variants(product_id, variant_code) ON DELETE CASCADE;

-- Drop FK
ALTER TABLE orders DROP CONSTRAINT fk_orders_users;
```

### Deferrable FK (checked at COMMIT, not INSERT)

```plsql
ALTER TABLE orders ADD CONSTRAINT fk_orders_users
    FOREIGN KEY (user_id) REFERENCES users(id)
    DEFERRABLE INITIALLY DEFERRED;

-- Now you can insert in any order within a transaction
BEGIN;
    INSERT INTO orders (user_id) VALUES (999);  -- user 999 doesn't exist yet
    INSERT INTO users (id, username) VALUES (999, 'new_user');
COMMIT;  -- FK check happens here — passes
```

| Deferrability | Check timing |
|--------------|-------------|
| `NOT DEFERRABLE` (default) | After each statement |
| `DEFERRABLE INITIALLY IMMEDIATE` | Can defer, starts immediate |
| `DEFERRABLE INITIALLY DEFERRED` | At COMMIT only |

## FK Indexing

**Best practice:** Index every FK column unless you have a reason not to.

```plsql
CREATE INDEX idx_orders_user_id ON orders(user_id);
CREATE INDEX idx_inventory_variant ON variant_inventory(product_id, variant_code);
CREATE INDEX idx_orders_user_id_nonnull ON orders(user_id) WHERE user_id IS NOT NULL;
```

**Skip indexing when:** Table is tiny (under 1000 rows), FK has very low cardinality (e.g., boolean status), table is write-only.

## Gotchas

### Primary Key

| # | Gotcha |
|---|--------|
| 1 | PK columns are NOT NULL implicitly — no need to write it |
| 2 | `SERIAL` is sugar for `INTEGER + sequence`. Use `GENERATED AS IDENTITY` (PG10+) |
| 3 | Composite PK index order matters: `PK(a,b)` ≠ `PK(b,a)` for query perf |
| 4 | PK can be UUID: `id UUID DEFAULT gen_random_uuid() PRIMARY KEY` |
| 5 | PK index is for lookup, not physical row order |
| 6 | Changing PK column type requires dropping the PK first |

### Foreign Key

| # | Gotcha |
|---|--------|
| 1 | FKs are NOT auto-indexed — create indexes manually |
| 2 | NULL FK = no relationship (not checked against parent) |
| 3 | Composite FK requires ALL columns to match (partial = failure) |
| 4 | If ANY column in composite FK is NULL, entire FK is treated as NULL |
| 5 | Self-referencing FK: delete children before parents (or use CASCADE/SET NULL) |
| 6 | `ON DELETE CASCADE` is silent — can delete thousands of rows without warning |
| 7 | Circular FK refs need deferrable constraints or order-of-operations tricks |
| 8 | Every FK insert checks the parent — slow on bulk operations |

## Complete Example — University Schema

```plsql
CREATE TABLE students (
    id          INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    student_id  VARCHAR(20) NOT NULL UNIQUE,
    name        VARCHAR(100) NOT NULL,
    email       VARCHAR(255) NOT NULL UNIQUE
);

CREATE TABLE courses (
    course_code VARCHAR(10) PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    credits     INT NOT NULL CHECK (credits > 0)
);

-- Composite PK + single-column FKs
CREATE TABLE enrollments (
    student_id  INT NOT NULL,
    course_code VARCHAR(10) NOT NULL,
    semester    VARCHAR(10) NOT NULL,
    grade       CHAR(2),
    enrolled_at TIMESTAMPTZ DEFAULT NOW(),
    CONSTRAINT pk_enrollments PRIMARY KEY (student_id, course_code, semester),
    CONSTRAINT fk_enroll_student FOREIGN KEY (student_id)
        REFERENCES students(id) ON DELETE CASCADE,
    CONSTRAINT fk_enroll_course FOREIGN KEY (course_code)
        REFERENCES courses(course_code) ON DELETE RESTRICT
);

-- Composite PK + composite FK referencing enrollments
CREATE TABLE course_schedule (
    student_id      INT NOT NULL,
    course_code     VARCHAR(10) NOT NULL,
    semester        VARCHAR(10) NOT NULL,
    day_of_week     VARCHAR(3) NOT NULL,
    start_time      TIME NOT NULL,
    end_time        TIME NOT NULL,
    room_number     VARCHAR(20),
    CONSTRAINT pk_schedule PRIMARY KEY (student_id, course_code, semester, day_of_week, start_time),
    CONSTRAINT fk_schedule_enroll FOREIGN KEY (student_id, course_code, semester)
        REFERENCES enrollments(student_id, course_code, semester) ON DELETE CASCADE
);

CREATE INDEX idx_enrollments_student ON enrollments(student_id);
CREATE INDEX idx_enrollments_course ON enrollments(course_code);
CREATE INDEX idx_schedule_enroll ON course_schedule(student_id, course_code, semester);
```

## Cheat Sheet

```plsql
-- ==================== PRIMARY KEY ====================
CREATE TABLE t (id INT PRIMARY KEY);                          -- column-level
CREATE TABLE t (a INT NOT NULL, b INT NOT NULL,               -- composite (table-level)
    CONSTRAINT pk_t PRIMARY KEY (a, b));
ALTER TABLE t ADD PRIMARY KEY (id);                           -- add to existing
ALTER TABLE t ADD CONSTRAINT pk_t PRIMARY KEY (a, b);
ALTER TABLE t DROP CONSTRAINT t_pkey;                         -- drop
ALTER TABLE t DROP CONSTRAINT t_pkey CASCADE;                 -- drop + remove refs

-- ==================== FOREIGN KEY ====================
CREATE TABLE child (pid INT REFERENCES parent(id));           -- column-level
CREATE TABLE child (pid INT NOT NULL,                         -- table-level, named
    CONSTRAINT fk_child_parent FOREIGN KEY (pid)
        REFERENCES parent(id) ON DELETE CASCADE);
CREATE TABLE child (a INT NOT NULL, b INT NOT NULL,           -- composite FK
    CONSTRAINT fk_child_parent FOREIGN KEY (a, b)
        REFERENCES parent(a, b) ON DELETE CASCADE);
CREATE TABLE emp (id INT PRIMARY KEY, mgr_id INT REFERENCES emp(id)   -- self-ref FK
    ON DELETE SET NULL);

ALTER TABLE child ADD CONSTRAINT fk_child_parent              -- add to existing
    FOREIGN KEY (pid) REFERENCES parent(id);
ALTER TABLE child DROP CONSTRAINT fk_child_parent;            -- drop
ALTER TABLE child ADD CONSTRAINT fk_child_parent              -- deferrable FK
    FOREIGN KEY (pid) REFERENCES parent(id)
    DEFERRABLE INITIALLY DEFERRED;

-- ==================== FK INDEXES ====================
CREATE INDEX idx_child_parent ON child(pid);
CREATE INDEX idx_child_composite ON child(a, b);
```
