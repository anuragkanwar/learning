# 10.2 How Transactions Work (The Proxy Mechanism)

## It's AOP Under the Hood

`@Transactional` is implemented using **Spring AOP (Aspect-Oriented Programming)**.

When you annotate a method with `@Transactional`, Spring creates a **Proxy** around your bean.

```
┌─────────────────────────────────────────┐
│           Your Code Calls               │
│    paymentService.processPayment()      │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│        Transactional Proxy              │
│  (Generated by Spring at runtime)       │
│                                         │
│  1. Start Transaction                   │
│  2. Call Real Method                    │
│  3. Commit or Rollback                  │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│       Real PaymentService               │
│     (Your actual class)                 │
│                                         │
│     processPayment() { ... }            │
└─────────────────────────────────────────┘
```

---

## The Execution Flow

```java
@Transactional
public void processPayment() {
    debit();   // Step 1
    credit();  // Step 2
}
```

**Actual execution:**
1. Client calls `processPayment()` → hits the **Proxy**
2. Proxy starts transaction (gets connection, sets autoCommit=false)
3. Proxy calls **real** `processPayment()` method
4. `debit()` executes (but doesn't commit yet — transaction is open)
5. `credit()` executes (still same transaction)
6. Real method returns to Proxy
7. Proxy checks: Did an exception occur?
   - **No exception** → Proxy commits transaction
   - **Exception thrown** → Proxy rolls back transaction
8. Connection returned to pool

## Proxy Types

Spring uses two proxy mechanisms:

| Proxy Type | When Used | Characteristic |
|------------|-----------|----------------|
| **JDK Dynamic Proxy** | Class implements interface | Interface-based proxy |
| **CGLIB Proxy** | Class has no interface | Extends your class (subclass proxy) |

```java
// If PaymentService implements PaymentInterface
// → JDK Proxy created implementing PaymentInterface

// If PaymentService is just a class
// → CGLIB Proxy created extending PaymentService
```

:::note Modern Spring Boot
Spring Boot 2.0+ defaults to **CGLIB proxies** (`spring.aop.proxy-target-class=true`) to avoid proxy type issues.
:::

## Transaction Synchronization

How does the Proxy ensure all database operations use the same connection?

Spring uses `TransactionSynchronizationManager` — a ThreadLocal storage:

```java
// Simplified concept:
ThreadLocal<Map<DataSource, ConnectionHolder>> resources;

// When transaction starts:
resources.set(dataSource, connection);  // Bind connection to thread

// When repository executes SQL:
Connection conn = resources.get(dataSource);  // Get same connection
stmt.execute();  // Uses bound connection

// When transaction ends:
resources.remove(dataSource);  // Unbind and return to pool
```

**Key Point:** All database operations in the same thread use the **same connection** during a transaction.
